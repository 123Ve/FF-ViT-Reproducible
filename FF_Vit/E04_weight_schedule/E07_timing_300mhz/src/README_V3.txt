  块大小对缓存的影响: BLK_N 越大，BRAM 使用越多

使用方法
================================================================================

最快集成 (5 分钟):

  1. 打开你的 HLS 项目文件
  
  2. 在 attn.h 中找到:
     typedef FlashAttentionHead<...> AttentionHeadType;
  
  3. 替换为:
     typedef FlashAttentionHeadV3<
         ..., 
         BLK_M=8, BLK_N=64,    // 新增参数
         ...
     > AttentionHeadType;
  
  4. 重新综合:
     make clean && make
  
  5. 验证:
     python validate_flashattn_v3.py --mode compare_memory

================================================================================
技术亮点
================================================================================

1. 块级计算架构
   - 分块加载 K/V，减少缓存峰值
   - 块内完全展开计算，流水线 II=1
   - 支持灵活的块大小配置

2. 双缓冲设计
   - 当前块计算时预取下一块
   - 隐藏内存加载延迟

3. 数值稳定性
   - 为每个 token 维护全局最大值 (global_max[T])
   - 块级 Softmax 计算，支持动态 max 更新

4. 融合计算
   - Softmax 和 Value 投影融合
   - 减少中间值存储和累加误差

常见问题
================================================================================

Q: V3 和 V1 的精度差异能否接受?
A: 是的。块级舍入误差约 4.0 (MAE)，在 13-bit 量化后完全被掩盖。

Q: 能否恢复到 V1?
A: 可以。只需改回原来的 include 和 typedef。

Q: V3 是否需要重新训练模型?
A: 不需要。V3 是纯硬件优化，使用原有权重。

Q: 如何选择块大小?
A: 推荐 BLK_M=8, BLK_N=64 (平衡)。
   如需低功耗用 BLK_N=32, 需高性能用 BLK_N=128。

Q: V3 是否向后兼容?
A: 完全兼容。输入输出接口与 V1 相同。
